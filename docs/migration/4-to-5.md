# Concinno 4.x → 5.0 Migration Guide

**Audience**: operators upgrading a 4.x install to 5.0.0.

**TL;DR**: 5.0.0 is a **SEMVER-MAJOR breaking release** because 27 SOTA
guards previously shipped default-off were promoted to default-on. If
you trust the 4.x default-off baseline, run **one command** to keep it:

```bash
concinno features disable-all-d-class
```

If you want the 5.0.0 default-on behaviour (recommended), do nothing —
`pip install --upgrade concinno` is sufficient.

## Why 5.0.0 broke compatibility

The 4.0.0 release flipped 27 hard-gate / soft-gate features default-off
to give senior operators a permissive baseline. The 2026-04-29 8-axis
evidence-driven audit found those 27 features had accumulated **zero
production trace** — they were the work product of major feature waves
(security guards, CBUA gates, skill emergence, operational guards) but
no operator ever opted in, so they may as well not have shipped.

The 5.0.0 SEMVER-MAJOR release fixes this by making the default the
*intended* baseline (default-on) and exposing an explicit one-liner
opt-out for the small fraction of operators who consciously want the
4.x default-off baseline.

This is a behaviour change, hence SEMVER-MAJOR. Existing config in
`~/.concinno/feature_overrides.json` and per-project `cc_config.json`
**continues to work unchanged** — the 6-source resolution chain
already prefers user overrides over shipped defaults. The only
operators affected are those who relied on the 4.x **default**
(never overrode anything) and want that default preserved.

## Retained default-off (3 features)

These three features remain **default-off** in 5.0.0:

| Feature | Reason |
| --- | --- |
| `release_authorization` | Sovereign user opt-out via `~/.concinno/release_auth.json` (publish-authorization permanent opt-out directive 2026-04-27, after >10 user corrections) |
| `dspy_prompt_optimization` | Cost-bearing API op — must remain explicit opt-in until budget guard ships |
| `premise_gate` | External module without a `FEATURE_META` entry; retained at user discretion via `cfg.feature('premise_gate', 'enabled', True)` or `CONCINNO_PREMISE_GATE=1` |

## Opt-out paths

### One-liner (recommended for 4.x trust users)

```bash
concinno features disable-all-d-class
```

This is an alias for `concinno features set-profile 4-x-compat`. It
writes `enabled=False` for all 27 D-class features into
`~/.concinno/feature_overrides.json`. Idempotent — re-running yields
zero diff.

### Per feature

```bash
# In-process (one Python session)
python -c "from concinno.core.config import get_config; \
  get_config().set_feature('butterfly_guard', 'enabled', False)"

# Persistent (user-level)
cat >> ~/.concinno/feature_overrides.json <<'EOF'
{"butterfly_guard": {"enabled": false}}
EOF

# Per-session env var
export CONCINNO_BUTTERFLY_GUARD_ENABLED=0
```

The 6-source resolution chain (env > user > project > FEATURE_META)
ensures any of the above overrides the shipped 5.0.0 default.

### Other profiles

If you want a different baseline:

| Profile | Effect |
| --- | --- |
| `lite` | DestructionGuard hard-deny only; everything else silent / warn |
| `mainstream` | Production-ready balance — hard-deny on data-loss + secrets, warn+log on quality gates |
| `strict` | Pre-4.0.0 paranoid baseline — enables every feature in `DEFAULT_OFF_4_0_0` (now 3 features in 5.0.0) |
| `paranoid` | Every guard hard-denies except cosmetic / observability features |
| `dev` | Solo-dev productivity — `dspy_prompt_optimization` + `polling_watcher` + `pip_aftermath_hint` only |
| `4-x-compat` | **NEW in 5.0.0** — restore the 4.x default-off baseline for the 27 D-class features |

```bash
concinno features set-profile mainstream  # or any of the above
```

## What did NOT change

- The 6-source feature-resolution chain
  (env > user > project > FEATURE_META) is unchanged.
- All public APIs (`Config`, `cfg.feature(...)`, `apply_feature_toggle_profile`)
  are unchanged.
- `~/.concinno/feature_overrides.json` schema is unchanged.
- The destruction guard (R0–R4 data-deletion patterns) was already
  hard-deny in 4.x and remains so in 5.0.0.
- The publish-authorization opt-out via
  `~/.concinno/release_auth.json` continues to work unchanged.

## Verifying the upgrade

```bash
python -c "
from concinno.feature_config import D_CLASS_5_0_0, meta_enabled_default
for name in sorted(D_CLASS_5_0_0):
    print(f'  {name:30s} default-on: {meta_enabled_default(name)}')
"
```

A fresh 5.0.0 install with no user overrides prints `default-on: True`
for all 27 entries. After `concinno features disable-all-d-class`,
`Config.feature(name, 'enabled')` returns `False` for all 27 (the
override file wins over the shipped default; the underlying
`meta_enabled_default(name)` still reports `True` because that helper
reflects the *shipped* default, not the resolved value).

## Sediment

The vaporware pathology behind 5.0.0 is documented in
`feedback_default_off_features_become_vaporware.md` (MEMORY #4s) and
the CHANGELOG `[5.0.0]` entry. The bar for shipping a new feature
default-off in 5.0.0+ is now: the same commit must justify the choice
as **cosmetic** / **opt-in by design** (e.g. `release_authorization`)
/ **safety opt-in** (e.g. `dspy_prompt_optimization`). Any other
default-off is a review block.

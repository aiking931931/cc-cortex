## Lazy-load strategy

All CLI commands import heavy deps (`json`, `pathlib`) only at call time. Module-level imports are `from __future__ import annotations` + stdlib-only. `publish_cmd` defers `twine` subprocess to runtime.

## ZIQ alignment

- `session_switches`: non-autotunable (user controls top-N). Future hook: count which switches get consulted most; auto-promote into summary.
- `configure_permissions`: non-autotunable by default (safe set is hardcoded). Future: ZIQ learns which bash patterns user accepts/denies most to promote.
- `publish`: not ZIQ-aligned (irreversible decision, no exploration).
- `config_preservation`: invariant layer, not ZIQ.

## CBUA optimality — red-team self-review before commit

1. **Scenario premise**: CLI subscription, not API billing — no cost model attack valid.
2. **Preserve-destructive default=True** for `configure-permissions` — destruction_guard stays locked even if user opts into "all safe".
3. **Platform ceiling**: host permission gate can't be bypassed for in-session bash; `publish` runs in user's own terminal by design.
4. **Advantages not smeared**: per-feature switches are the core product, not bloat.

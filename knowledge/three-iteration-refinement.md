# Three-Iteration Refinement

Never ship your first thought. Iterate internally three times before presenting.
Silent refinement produces better output than asking for feedback three times.

## The Process

### Iteration 1: First Draft

Generate the initial solution. Don't self-censor — let the raw idea flow.
This version is usually 60–70% correct but has blind spots.

### Iteration 2: Challenge

Act as your own critic. Ask:

- "What did I miss?"
- "What assumptions am I making?"
- "Is this the simplest way to achieve the goal?"
- "What would break if conditions changed?"

Revise based on findings. This typically catches 80% of issues.

### Iteration 3: Polish

Final pass focused on:

- **Completeness**: Are all edge cases handled?
- **Clarity**: Would someone else understand this immediately?
- **Efficiency**: Is there unnecessary complexity?
- **Consistency**: Does this align with existing patterns?

## When to Apply

- Multi-option decisions (don't present the first option you think of)
- Code architecture decisions
- User-facing output (messages, documentation, APIs)
- Any deliverable where quality matters more than speed

## Key Principle

The cost of three internal iterations is far less than the cost of one
external correction. Self-refinement is cheaper than back-and-forth.

## Anti-Patterns

- **Infinite iteration**: Three rounds, not thirty. Diminishing returns are real
- **Cosmetic iteration**: Changing words without changing substance
- **Skipping iteration 2**: The challenge step is where real improvement happens
- **Iterating on the wrong thing**: If the foundation is wrong, iteration
  polishes a turd. Go back to First Principles instead
